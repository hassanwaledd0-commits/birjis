# النشر على Netlify

العنوان الرسمي مكتوب بمكان واحد فقط: `site_url` في `site.config.json` (الآن `https://birjis3.netlify.app/`).
كل الروابط (canonical، صورة المشاركة، JSON-LD، `sitemap.xml`، `robots.txt`) تُبنى منه.

## 1. بناء حزمة النشر

```bash
./check.sh          # يبني ويفحص كل شي (أو: ./build.sh && python3 tools/mksite.py)
```

النتيجة:

| المجلد | لأي موقع | شنو بيه |
|---|---|---|
| `dist/site/` | الموقع الجديد birjis3 | `index.html`، `logo.png`، `og.png`، `sitemap.xml`، `robots.txt`، `_headers`، `_redirects`، `netlify.toml` |
| `dist/old-site/` | الموقع القديم birjis | تحويل دائم (301) لكل رابط إلى نفس المسار على العنوان الجديد |

## 2. رفع الموقع الجديد (birjis3)

1. Netlify ← موقع **birjis3** ← تبويب **Deploys**.
2. اسحب **مجلد `dist/site` كله** وأفلته بمربع الرفع. لا ترفع `index.html` وحده:
   بدون `_headers` ما تشتغل رؤوس الأمان، وبدون `og.png` تطلع المشاركة بلا صورة، وبدون `robots.txt` و`sitemap.xml` محركات البحث ما تلگى الخريطة.
3. بعد النشر افتح هذني وتأكد كلهن يفتحن (مو 404):
   `https://birjis3.netlify.app/robots.txt` · `https://birjis3.netlify.app/sitemap.xml` · `https://birjis3.netlify.app/og.png`

## 3. تحويل العنوان القديم (birjis)

1. Netlify ← موقع **birjis** (القديم) ← **Deploys**.
2. اسحب **مجلد `dist/old-site`** وأفلته.
3. جرّب `https://birjis.netlify.app/` لازم يحوّلك تلقائياً لـ `https://birjis3.netlify.app/`.

بهالطريقة محركات البحث تنقل ترتيب الموقع القديم للجديد، وأي رابط قديم منشور يبقى يشتغل.

## 4. إذا تغيّر العنوان بالمستقبل

غيّر `site_url` بـ`site.config.json`، وحط العنوان القديم داخل `old_urls`، وأعد الخطوات 1 إلى 3. الفحص (`tools/check_links.py`) يفشل إذا بقى أي رابط على العنوان القديم.

## 5. ميسلون على الموقع (الذكاء الاصطناعي بثلاث طبقات)

ميسلون والمدرّس الذكي والكاميرا يجربون بالترتيب، وإذا فشلت طبقة ينتقلون للي بعدها تلقائياً، وسطر صغير تحت كل صندوق يگول أي وضع شغال:

| الطبقة | متى تشتغل | تحتاج شنو |
|---|---|---|
| أ. Claude داخل الصفحة | لما الصفحة مفتوحة كـartifact داخل Claude | ولا شي |
| ب. خادم الموقع | على Netlify | دالة `netlify/functions/ask.mjs` منشورة + مفتاح `ANTHROPIC_API_KEY` |
| ج. محلي بدون إنترنت | دائماً | ولا شي: يجاوب من الدروس والقطع والقاموس وبطاقات AMM مع رابط للمصدر |

الكاميرا تحتاج أ أو ب. بدونهن تطلع قائمة «اختر القطعة يدوياً».

### تفعيل الطبقة ب (مرة وحدة)

1. **المفتاح:** Netlify ← موقع birjis3 ← **Site configuration ← Environment variables ← Add a variable**:
   الاسم `ANTHROPIC_API_KEY` والقيمة مفتاحك من console.anthropic.com. **لا تحط المفتاح بأي ملف أو بالكود.**
2. **حد للمصروف:** بـconsole.anthropic.com حط حد شهري للصرف (Limits). هذا هو السقف الحقيقي للكلفة.
3. **النشر مع الدالة:** السحب والإفلات لمجلد `dist/site` **ما ينشر الدالة**. استعمل وحدة من هذني:
   - ربط المستودع بـNetlify (Import from Git): يقرأ `netlify.toml` بجذر المشروع ويبني الصفحة والدالة وحده.
   - أو من جهازك بجذر المشروع: `npm ci` ثم `npx netlify-cli deploy --build --prod`.
4. **التجربة:** افتح الموقع ← «اسأل ميسلون» ← اسأل سؤال. السطر تحت الصندوق لازم يگول «الوضع: خادم الموقع (Claude)».

### الحدود الموجودة

- قاعدة Netlify: 8 طلبات بالدقيقة لكل زائر (`config.rateLimit` بالدالة)، وفوقها 30 طلب كل 10 دقايق لكل عنوان IP بذاكرة الدالة.
- طول الطلب 20000 حرف كحد أعلى، وخانة السؤال 600 حرف، وصورة وحدة بحجم محدود، والجواب 3000 توكن كحد أعلى.
- الطلب لازم يجي من نفس الموقع (الدالة ترفض أي موقع ثاني).
- النموذج الافتراضي `claude-opus-5-5`. إذا تريد أرخص بكثير، ضيف متغير `BIRJIS_AI_MODEL` بقيمة `claude-haiku-5-5` (قرارك).
- إذا Claude رفض سؤال، يرجع جواب مهذب، ومفعّل الانتقال التلقائي لنموذج احتياطي (`fallbacks: "default"`).
